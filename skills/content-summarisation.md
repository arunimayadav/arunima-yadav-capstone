Name: content-summarisation
Description: Produces a short, plain-language summary of what a file is actually about, independent of its classification category. This becomes part of the file's retrievable metadata record, not a substitute for it.

Content Summarisation Skill

Input
content_excerpt: extracted text/content from the file, to summarise
category: category from Classification, if available, useful context but not a substitute for a summary
doc_type: document type from Classification, if available, useful context for framing the summary
title_source: extracted text excerpt and/or original filename, for extra context when content_excerpt is thin

Step 1: Read the content, not the label
Base the summary on what content_excerpt actually says, not on what category or doc_type imply it should say.
Category and doc_type describe where the file lives and what kind of document it is, they don't describe its subject matter, don't let them stand in for reading the content.
If content_excerpt is thin or unreadable (e.g. a scanned image with no OCR text, a mostly-visual file), fall back to title_source and say so plainly rather than guessing at content that isn't there.

Step 2: Write a short, plain-language summary (15-25 words)
State what the file is actually about, in plain sentences a person could read at a glance and immediately know whether this is the file they're looking for.
Length: one to three sentences. Long enough to be useful, short enough to stay skimmable in a metadata record.
Be concrete: name the actual subject, the actual people/topics/numbers involved, not vague description ("This document discusses a topic" is not a summary).
Plain language over jargon, write for whoever is searching later, not for the file's own domain vocabulary.

Rules
The summary is independent of classification, two files in the same category and doc_type can (and often will) have completely different summaries.
Never pad the summary with information already captured elsewhere in the metadata record (filename, category, tags, date), the summary's job is content, not restating other fields.
Don't editorialise or evaluate the file's quality/importance, describe what it is about, not whether it's good.
If the file is unreadable or content_excerpt is empty, say that directly (e.g. "No extractable text; filename suggests this is a photo from the Design Thinking trip.") rather than fabricating a plausible-sounding summary.
This summary supplements the file's metadata record, it does not replace category, tags, or doc_type, each of those still gets generated by its own skill.
